# Data Dictionary – My Brick Company (MBC)

> **All data is synthetic.** My Brick Company (MBC) is a fictional manufacturer; the dataset covers its packaging plant
> in Central Bohemia. No real company, supplier or person is represented.

Generated by `python generator/generate_data.py` (fixed seed → identical output on every run).
Outputs: `data/csv/*.csv` (for Power BI) and `data/mbc.db` (SQLite, same tables).

- **Period:** 09/2024 – 09/2026 (25 months), one plant `CZ01`, local currency **CZK**
- **Formats:** dates `YYYY-MM-DD`, decimal point `.`, UTF-8
  (in a Czech Power BI install set the import locale to *English (United States)*)
- **Naming:** table names follow the SAP table they imitate; column names are readable
  English (as in a typical BI layer). The original SAP field is listed for each column.

## 2. Relationships

```
lfa1_vendors 1 ──< N ekko_po_header 1 ──< N ekpo_po_items 1 ──< N goods_receipts
      │                                        │      │                 │
      └──────────────< N invoices >────────────┘      │                 │ (gr_id)
                          └────────────────────────────────────────────┘
mara_materials 1 ──< N ekpo_po_items / goods_receipts / invoices / consumption /
                       stock_snapshot / mbew_valuation
fx_rates: joined by (currency, first day of month) to convert EUR/PLN to CZK
```

| From | To | Key | Cardinality |
|---|---|---|---|
| `ekko_po_header` | `lfa1_vendors` | `vendor_id` | N : 1 |
| `ekpo_po_items` | `ekko_po_header` | `po_number` | N : 1 |
| `ekpo_po_items` | `mara_materials` | `material_id` | N : 1 |
| `goods_receipts` | `ekpo_po_items` | `po_number` + `po_item` | N : 1 (partial deliveries → 2 receipts) |
| `invoices` | `ekpo_po_items` | `po_number` + `po_item` | N : 1 |
| `invoices` | `goods_receipts` | `gr_id` | 1 : 1 (empty = invoice without GR) |
| `mbew_valuation` | `mara_materials` | `material_id` (+ `valuation_year`) | N : 1 |
| `consumption`, `stock_snapshot` | `mara_materials` | `material_id` | N : 1 |

**Power BI hint (star schema):** `ekpo_po_items` needs `po_date`, `vendor_id` and `currency` from
`ekko_po_header` → merge the header into the items in Power Query, so the fact table connects
directly to the Vendor and Date dimensions.

## 3. Master data

### `lfa1_vendors` – vendors (SAP LFA1)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `vendor_id` | text (PK) | LFA1-LIFNR | Vendor number, e.g. `V10001` |
| `vendor_name` | text | LFA1-NAME1 | Vendor name (fictional) |
| `country` | text | LFA1-LAND1 | ISO country code (CZ, DE, AT, SK, NL, PL) |
| `currency` | text | LFM1-WAERS | Order currency: CZK / EUR / PLN |
| `payment_terms` | text | LFM1-ZTERM | `Z030` / `Z045` / `Z060` = net 30 / 45 / 60 days |

Indirect-spend vendors (energy, facility, construction, services) are always local (CZK).

### `mara_materials` – materials (SAP MARA)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `material_id` | text (PK) | MARA-MATNR | Material number, e.g. `M100001` |
| `description` | text | MAKT-MAKTX | Short text |
| `category` | text | MARA-MATKL | Material group: Folding cartons, Labels, Energy, … (11 groups) |
| `spend_type` | text | – (derived) | `direct` = goes into the product; `indirect` = runs the plant |
| `material_type` | text | MARA-MTART | `VERP` packaging (stock, valuated), `DIEN` service, `NLAG` non-stock (energy) |
| `uom` | text | MARA-MEINS | Base unit: KS (piece), KG, BAL (pack), MWH, HOD (hour), SLU (service unit) |
| `lead_time_days` | integer | MARC-PLIFZ / EINE-APLFZ | Planned delivery time in days |
| `moq` | number | EINE-MINBM | Minimum order quantity (base unit) |

Only `direct` materials have stock, consumption and a standard price.

### `mbew_valuation` – standard price per year (SAP MBEW / MBEWH)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `material_id` | text (FK) | MBEW-MATNR | Material |
| `valuation_year` | integer | – (MBEWH-LFGJA) | Year the price is valid for |
| `valid_from` | date | – | Always 1 January (annual cost estimate / price update) |
| `price_control` | text | MBEW-VPRSV | `S` = standard price (`V` would be moving average) |
| `standard_price_czk` | number | MBEW-STPRS | Standard price per base unit in CZK |

The standard price is set once a year = average market price of the previous year ± 2 %.
It is the baseline for **PPV**.

### `fx_rates` – exchange rates (SAP TCURR)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `month` | date | TCURR-GDATU | First day of the month |
| `from_currency` | text | TCURR-FCURR | EUR or PLN |
| `to_currency` | text | TCURR-TCURR | Always CZK |
| `actual_rate` | number | rate type M | Average actual rate of the month |
| `plan_rate` | number | rate type P | Plan (budget) rate for the year = average actual rate of the previous year |

History starts 01/2024 so that the 2025 plan rate can be derived. CZK rows do not exist (rate = 1).

## 4. Transactions

### `ekko_po_header` – purchase order header (SAP EKKO)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `po_number` | text (PK) | EKKO-EBELN | PO number, `4500000001` … (numbered by date) |
| `po_date` | date | EKKO-BEDAT | PO document date |
| `vendor_id` | text (FK) | EKKO-LIFNR | Vendor |
| `currency` | text | EKKO-WAERS | PO currency (= vendor currency) |
| `buyer` | text | EKKO-EKGRP | Purchasing group / buyer (fictional) |

### `ekpo_po_items` – purchase order items (SAP EKPO + EKET)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `po_number` | text (PK, FK) | EKPO-EBELN | PO number |
| `po_item` | integer (PK) | EKPO-EBELP | Item number 10, 20, 30 … |
| `material_id` | text (FK) | EKPO-MATNR | Material |
| `plant` | text | EKPO-WERKS | Plant (`CZ01`) |
| `quantity` | number | EKPO-MENGE | Ordered quantity in `order_uom` |
| `order_uom` | text | EKPO-MEINS | Order unit (normally = material base unit) |
| `net_price` | number | EKPO-NETPR | Net price per order unit, **in PO currency** |
| `net_value` | number | EKPO-NETWR | `quantity × net_price`, in PO currency |
| `requested_delivery_date` | date | EKET-EINDT | Requested delivery date (schedule line) – basis for OTIF |

Foreign-currency prices are agreed in EUR/PLN using the yearly plan rate, so the CZK cost
moves with the actual exchange rate (→ FX effect in PPV).

### `goods_receipts` – goods receipts, movement type 101 (SAP MSEG / MATDOC)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `gr_id` | text (PK) | MSEG-MBLNR | Material document number `5000000001` … |
| `po_number`, `po_item` | text / integer (FK) | MSEG-EBELN / EBELP | PO item received |
| `material_id` | text (FK) | MSEG-MATNR | Material |
| `plant` | text | MSEG-WERKS | Plant |
| `posting_date` | date | MKPF-BUDAT | Receipt date – compared with `requested_delivery_date` for OTIF |
| `quantity` | number | MSEG-MENGE | Received quantity in base unit |
| `amount_czk` | number | MSEG-DMBTR | Receipt value in CZK = quantity × PO price × actual rate of the month |
| `movement_type` | text | MSEG-BWART | `101` = goods receipt for PO |

Partial deliveries: first receipt 70–95 %, remainder 5–15 days later (second row).
For services the "goods receipt" represents the service confirmation (service entry sheet).

### `invoices` – supplier invoices (SAP RBKP / RSEG, transaction MIRO)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `invoice_id` | text (PK) | RBKP-BELNR | Invoice document `5105600001` … |
| `invoice_date` | date | RBKP-BLDAT | Invoice date |
| `vendor_id` | text (FK) | RBKP-LIFNR | Invoicing vendor |
| `po_number`, `po_item` | text / integer (FK) | RSEG-EBELN / EBELP | PO item invoiced |
| `gr_id` | text (FK) | RSEG-LFBNR | Reference goods receipt (**empty = invoice without GR**) |
| `material_id` | text (FK) | RSEG-MATNR | Material |
| `quantity` | number | RSEG-MENGE | Invoiced quantity |
| `unit_price` | number | – (RSEG-WRBTR / MENGE) | Invoiced price per unit, in invoice currency |
| `amount` | number | RSEG-WRBTR | Invoice amount in invoice currency |
| `currency` | text | RBKP-WAERS | Invoice currency |
| `amount_czk` | number | – | Amount in CZK at the actual rate of the invoice month |
| `payment_block` | text | RBKP-ZLSPR | `R` = blocked for payment (price deviation > 2 % tolerance) |

**IPV (invoice price variance)** = (`unit_price` − PO `net_price`) × `quantity`.
~10 % of invoices deviate from the PO price (−3 % to +5 %).

### `consumption` – goods issue to production, movement type 261 (SAP MSEG / MATDOC)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `posting_date` | date | MKPF-BUDAT | Sunday of the week (weekly aggregated posting) |
| `material_id` | text (FK) | MSEG-MATNR | Material |
| `plant` | text | MSEG-WERKS | Plant |
| `quantity` | number | MSEG-MENGE | Consumed quantity in base unit |
| `movement_type` | text | MSEG-BWART | `261` = goods issue for production order |

### `stock_snapshot` – month-end stock (SAP MARD / MARDH)
| Column | Type | SAP field | Description |
|---|---|---|---|
| `snapshot_date` | date | – (MARDH-LFGJA/LFMON) | Month-end date; `2024-08-31` = opening stock |
| `material_id` | text (FK) | MARD-MATNR | Material |
| `plant` | text | MARD-WERKS | Plant |
| `stock_qty` | number | MARD-LABST | Unrestricted stock quantity in base unit |

Quantity only – like MARD in SAP. **Stock value = `stock_qty` × standard price** of the
year (from `mbew_valuation`). Reconciles exactly:
`opening stock + Σ receipts − Σ consumption = closing stock`.

## 5. Planted business patterns
What the dashboard should reveal (verified by `generator/check_patterns.py`):

| Pattern | Where it shows |
|---|---|
| Seasonality – order peak Q3–Q4 (pre-Christmas production) | PO items per month |
| Carton price increase from 2025 (corrugated board index) | PPV Folding cartons: +1.4 % (2024) → +5.4 % (2025) → +9.8 % (2026) |
| FX effect – EUR weakened slightly vs. CZK, PLN strengthened ~11 % | PPV split into price vs. FX effect |
| One large carton supplier (PL) with poor delivery | OTIF ≈ 80 % vs. ≈ 92 % for others |
| Invoice price deviations | ~425 invoices with IPV, ~210 blocked for payment |
| Slow movers (no movement 180+ days) | 24 materials = 10 % of stock materials |
| Overstock – one oversized last order (12 materials) | 31 materials with coverage > 120 days: 11 planted, 9 ordered above EOQ, 11 cheap C-items where EOQ itself covers 4–6 months |
| Batch size vs. EOQ | 15 % of materials ordered at 2–3× EOQ, 10 % at 0.3–0.5× EOQ |

## 6. Known data quality issues (intentional)
Planted for the *Data Quality* dashboard page. The exact list ("answer key") is in
`data/dq_answer_key.csv`, so detection rules can be tested against known ground truth.

| # | Issue | Table | Count | Detection rule | Business impact |
|---|---|---|---|---|---|
| 1 | **Duplicate vendor** (typo / upper-case variant of an existing name) | `lfa1_vendors` | 2 | Same country and same normalised name start | Spend of one supplier split across two IDs → understated in Pareto, weaker negotiation position, risk of duplicate payment |
| 2 | **Missing standard price** for 2026 | `mbew_valuation` | 6 materials | Direct material bought in 2026 without a 2026 row in MBEW | PPV cannot be calculated; stock value silently understated (blank × qty) |
| 3 | **Unit of measure mismatch** – ordered in BAL (1 BAL = 100 KS), material base unit KS | `ekpo_po_items` | 5 items | `order_uom` ≠ material `uom` | PO price per BAL vs. receipt in KS → wrong PPV/IPV and false "not in full" |
| 4 | **Invoice without goods receipt** | `invoices` | 8 | `gr_id` is empty | 3-way match fails; potential duplicate invoicing / payment for goods not received |

How to treat them in reporting: **do not silently drop them.** Exclude from the affected
KPI, but show them on the Data Quality page with count and CZK impact, and name the owner
who should fix the source (vendor master → purchasing master data team; standard price →
cost accounting; UoM → material master; invoice without GR → accounts payable + buyer).
